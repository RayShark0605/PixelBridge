# 可选文件反馈辅助传输

**简体中文** | [English](FEEDBACK_ASSISTED_TRANSFER.en.md)

更新：2026-10-31。本默认关闭功能已纳入 v1.1.0，维护者报告前一候选实机亲测通过；当前交付见[发布说明](RELEASE_V1.1.md)。下方本地测试数字属于 2026-10-21 候选，不等于量化提速或全部提供商认证。

## 1. 数据与控制的边界

- Encoder A → Decoder B 的全部文件载荷仍只从实际捕获像素恢复。辅助文件不包含源文件内容、编码载荷或任意命令。
- B → A 只传版本化的有界状态：身份摘要、耐久段完成位图、合格画面序号和最终验证结果。这是显式选择的反向控制面，不是隐藏的正向传输。
- 未启用时不启动反馈 helper，不创建反馈策略，使用原视觉调度、恢复清理和停止行为。预期接收速度先验仍是独立的 PAM4 可选项。
- 首版针对一个指定 Decoder、一个 Sender，以及可信且没有被克隆或回滚的 Encoder Session cache。状态 CRC 和目录锁不是认证；不适用于不可信写者或多个 Receiver 竞争。

## 2. 设置与普通传输

1. **B：打开 Decoder → 高级选项 → 可选辅助反馈。** 勾选“启用辅助反馈（发布状态）”，选择可写目录或专用文件。文件保存目录与反馈目录可以不同。
2. 目录模式写入 `PixelBridgeFeedback.pbfb`；专用文件模式使用所选文件名。建议使用独立的反馈子目录，不与输出/恢复文件混放；不要指定自己的其他文件。程序拒绝覆盖非反馈文件、目录、链接或冲突锁。
3. **A：在 Encoder 主窗口或右键传输页启用辅助反馈（只读）。** 选择 B 位置在 A 上对应的目录/文件；可以直接粘贴 UNC 映射路径。A 的文本路径与 B 不必相同，但必须最终指向同一状态文件。目录/文件类型也须对应。
4. 双端选择同名的标准、灰阶高速、PAM4 或 PAM4 Wide；然后照常选择源文件、保存目录、屏幕/ROI，先启动 B，再启动 A。反馈不自动启动传输，不改变显示器或映射配置。
5. B 显示“已完成，反馈监听中”后，建议保留监听，直到 A 显示接收方验证完成并自动安全停止，再在 B 点击“停止反馈监听”或关闭窗口。监听期间完成文件可读取和打开查看，但编辑、移动或删除前须先停止监听；停止即释放只读保护。

主/Shell 共用 Encoder 设置；Decoder 使用自己的设置。加载和配置校验只做路径词法检查，不在 UI/传输 owner 中访问映射目录。路径尚不存在、权限不足或映射暂时不可见时，辅助连接可以不可用，但视觉通道不依赖它。

B 等视觉 Session 确定输出/恢复路径并完成词法重叠检查后，才启动反馈 writer。反馈主文件及其 `.tmp` / `.previous` / `.lock` 与当前 final、`.part`、journal 或 journal 临时文件重叠时，只禁用辅助，不抢占接收文件。检查处理 Windows 大小写与词法路径规范化，不宣称任意祖先重定向、短名/命名空间别名或全部文件系统竞态均已证明；使用真正独立的反馈子目录仍是推荐配置。A 在状态文件出现前可以等待并重试只读。

## 3. 哪些信息可以改变发送

只有实际完成现有 `RecordCompletedSegment`、`CommitStoredSegment` 和 `storedSegments` 更新的段才能置位。FEC ready、CRC、估算百分比和速度×时间都不是段确认。

Encoder 同时校验完整 Session/Profile/layout/文件大小/段数、canonical SessionDescriptor 和 FinalManifest 的 BLAKE3、写者及 epoch、一致位图和序列，以及 **当前 Start 中确实成功 Submit 的画面序号**。仅租用、构建、失败提交、下一个序号或旧 Start 的画面不能授权自动停止。

合格观察通过完整的所选 Profile/同帧检查；Bootstrap-only、erased 或 cadence 计数不生成观察凭据。普通提示在 15 秒没有新合格观察后失效。反复读取同一快照或只增加心跳序号不续期；完成凭据不套短 TTL，但仍须属于当前 Start 和完整身份。

有效时在完整帧或空间 bank 提交边界退休已确认段的后续访问，最多保留六个编码段；未完成段保持确定性扫描/回访。编码字节、descriptor 和 repair-ID 高水位不因确认改变；提前结束访问只记实际提交服务，并安全退休已租未用 ID。失效后恢复原全文件覆盖及用户配置的无反馈先验，不把 ACK 永久写成 Sender 的已完成状态。

即使所有段都确认，没有最终凭据也不会停止或伪造零段 Session；仍以真实单段服务画面维持 Control 刷新。速度先验不能覆盖真实完成确认，也不能被报告成接收事实。

## 4. 最终完成、重启与文件安全

最终确认来自原有 WholeFileDigest、安全发布和最终文件重开复验。Encoder 收到的是接收方报告，不是自己独立读取最终文件；停止原因单独记为 `ReceiverVerified`，不与用户停止或超时混淆。

仅在启用反馈时，B 成功后保留既有 `.resume`，包括 Manifest、PublishIntent、reservation 和 completed records。B 重启会沿原恢复链重新验证最终文件长度、摘要和重开；恢复成功不是一次新的 rename 观察。缺失或损坏最终文件不能生成新的完成凭据，反馈文件中的旧位图从不反向导入恢复状态。删除保留日志会失去自动重启确认，但不会删除完成文件。

完成后不再把 Transport 交给 Outer FEC、不再写输出或增加 verified bytes；只观察同一 Session 的合格画面并更新终态。文件完成耗时冻结，监听起止和耗时单独记录。停止、关闭或下一次 Start 都必须正确结束旧监听；完成文件不会被降为“未发布”。

反馈启用时，最终重开摘要使用的普通单链接文件句柄持续保持只读保护，直到停止监听；验证与持有之间没有先关闭再重开的间隙。新 Start 的视觉观察不能沿用无保护的旧文件事实。已有写句柄、可写映射或提供者不支持导致保护不可得时，只禁用辅助终态，不放宽共享保护，不撤销已经正确完成的文件结果。

## 5. I/O 隔离、时延与失效

两个独立包均需要同目录 `PBFeedbackIo.exe`。helper 只处理状态文件；本机的版本化元数据管道不承载源文件或像素。隐藏进程受 Job Object 和显式句柄继承约束；每个 runtime 最多一个未确认退出的 helper、一个在途写入和一个待写最新快照，不派生无限线程或重试。

初始参数为约每秒读/写，段完成和终态及时合并；单操作五秒 watchdog。超时使当前 Start 的辅助连接不可用并终止 helper，确认退出前不另开进程；Stop 使用有限等待。普通读取错误可以在同一个活读者内恢复；被超时/异常终止的 helper 需显式停止再开始重试。以上周期不是现场最优参数或延迟承诺。

A 仅 `GENERIC_READ` + `OPEN_EXISTING`，不会创建测试文件或清理 B 的文件。B 独占锁，写全并 flush 自有临时文件；从同一已校验对象句柄把旧状态退休到固定 `.previous`，再以 **no-replace** 发布新快照，绝不按 pathname 覆盖并发新出现的文件。旧读句柄仍能读取旧完整对象，但切换可能极短缺席，A 安全回退，不承诺无间隙原子替换。

发布失败时仅尝试不覆盖地恢复旧快照；新目标冲突则保留两者，辅助不可用。占用的 `.previous` / `.tmp` / 锁不会自动删除或采用。请先停止双端并确认文件归属，再把残留移到备份位置、重新选择空的专用反馈位置并重新 Start；不要自动删除看不懂的文件。提供者不支持安全改名/清理时禁用辅助，不降级成不安全覆盖。

目录缓存、映射延迟和 disconnect 的结果依具体 redirector 而定；不修改全局 SMB/远控缓存，也不以 mtime 或轮询频率证明新鲜度。

## 6. 报告与验收边界

报告和 journal 增加独立的 `feedback` 对象（`PixelBridge.FileFeedbackTelemetry.1`）：requested/effective、等待/有效/过期/拒绝/不可用状态、接受/重复/拒绝/超时计数、有效耐久段数、退休服务访问数、观察序号、terminalPublished/terminalAccepted、receiverReportedCompletionMilliseconds，以及独立监听时间。关闭或未知事实使用 false/null；不记录反馈路径、任意反馈状态文本或文件载荷。

Encoder 原先不可得的 `receiverProgress`、`receiverEta`、`verifiedGoodput` 不被重定义。`skippedSegmentServiceVisits` 是退休访问事件，不是已节省字节、耗时或实测提速。普通报告已有的源/输出位置属于其既有诊断字段，不能因此宣称整份报告已无隐私信息。

本地覆盖 codec/恶意边界、文件安全与真实 helper、超时/重启、四模式 0/1/6/12/13 段的真实 FEC/Receiver/存储、空间 bank、过期回退、终态重启、实际新 Start 像素绑定、离屏 GUI 和 DPI。无 raster 的调度 probe 不冒充屏幕/远控试验。完整应用回归仍保留历史 Gray Fast late-join `12505 < 12000` 失败及缺真实 Replay 的跳过；不宣称全仓全绿。

真实映射可见性、缓存/断线、权限/占用、长时间运行和端到端收益由后续现场验证确认；比较同一候选的反馈关闭/开启，以最终摘要、发布和重开后的完成时间为准。[研究评估及在线来源](FEEDBACK_ASSISTED_TRANSFER_RESEARCH.md)、[设计](superpowers/specs/2026-10-21-feedback-assisted-transfer-design.md)、[项目现状](PROJECT_STATUS.md)。
