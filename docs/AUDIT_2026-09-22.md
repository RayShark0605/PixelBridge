# PixelBridge 全量代码与文档审计记录（2026-09-22）

## 1. 项目目标与当前阶段

PixelBridge 的目标是：在 Windows x64 上，通过已有远控/视频画面中的**可见像素**完成非本机、单向文件传输；Encoder 只显示码面，Decoder 只从实际捕获的所选屏幕区域恢复 payload。首要指标是从接收开始到 `WholeFileDigest`、安全发布和最终重开复验全部完成的正确文件总完成时间，而不是发送 FPS、理论 bits/cell 或 GPU 利用率。

当前阶段是**稳定性、v1.0 本地正式交付和 Encoder Shell 入口收口**，不是重新进行 Profile、密度或 FPS 扫描。旧的非本机 ToDesk 大文件记录、单物理显示器边界和一小时无停滞目标仍按现状/证据文档中的范围解释；本次审计没有把离屏、单元或历史现场记录升级为新的远控认证。

纯视觉单向边界保持不变：没有 socket、pipe、共享内存、COM、剪贴板、窗口消息、临时文件 payload 或隐式 ACK。摘要、安全发布、最终重开验证、冲突拒绝、Wirehair/资源准入和文件大小边界均未削弱。

## 3. 已确认并修复的问题

### 3.1 Shell 对话框的取消/关闭路径绕过安全停止交互

`ShellTransferDialog` 原先把 `QDialogButtonBox::rejected` 直接连到 `QDialog::reject`。活动传输时，Cancel 和 Qt 的 Esc 默认 reject 可能直接结束对话框；这绕过了“请求停止、等待 Controller 终态、再关闭”的专用 UI 路径。

修复：活动时设置 `closePending_`、禁用 Cancel 并调用 `RequestStop()`；覆盖 `reject()` 使 Esc 与按钮路径共用安全停止逻辑；非活动时显式调用 `QDialog::reject()`，避免递归。新增 `PBEncoderShellTests` 生命周期断言，并通过 GUI smoke 的非活动 reject 路径。

### 3.2 Shell 注册表冲突时错误发布显示名

原逻辑在检查 `command` 子键现有命令之前，就可能把空父键默认值写成 `PixelBridgeEncoder`。当用户已有同名、非 PixelBridge 所有的命令时，这会把第三方命令展示成 PixelBridgeEncoder verb。修复后只有新建或带 `PBRegistrationOwner=PixelBridgeEncoder.1` 的自有命令才会发布/修复显示名；非自有非空命令保持不动。新增冲突矩阵回归断言。

### 3.3 文件夹归档预检遗漏隐藏/系统条目

`QDirIterator` 原过滤器没有显式包含 `Hidden`/`System`，而 Windows `tar.exe` 会从目录根递归归档这些条目。这会让条目数、总字节数和 reparse 检查不完整。修复为 `AllEntries | Hidden | System | NoDotAndDotDot`，并在归档测试中加入隐藏文件，确认 ZIP 列表保留它。

归档仍是普通本地 ZIP 源文件，保留 1,000,000 条目/500 GiB 有界检查、reparse/symlink 拒绝和现有摘要/发布链路；没有增加 payload 旁路。

### 3.4 Qt cppcheck shim 导致静态审计覆盖缺口

Qt 关键字门禁使用 `-Dslots=` 等 shim。公共调制头和应用调度结构中存在名为 `slots` 的真实字段，导致 shim 把 `state.slots` 等表达式改写成非法语法；门禁因此 fail-closed，静态审计不能覆盖这些翻译单元。

修复为语义化字段：`slotObservations`、`slotInputs`、`slotAssignments`、`slotDecisions`、`slotData`，同步所有生产/测试/诊断引用。该改动只改变 C++ 源字段名，不改变序列化字节、Profile、FEC、光栅或运行时 wire 行为。

### 3.5 Shell 对话框空闲 Escape 无法取消

Shell 对话框的 `QShortcut(Qt::Key_Escape)` 仍直接连接 `EncoderApplicationController::RequestStop()`；在传输尚未开始时 Controller 不活跃，该快捷键既不关闭对话框，也不走 Cancel/reject 路径。修复为与 Cancel 共用 `HandleCancel()`：空闲时执行标准 reject，活动时设置 `closePending_`、禁用 Cancel、请求安全停止并等待终态。离屏 smoke 现在显式触发该快捷键并断言对话框关闭。

### 3.6 文件夹名以 `-` 开头时 tar 参数解析失败

用真实 Windows `System32\tar.exe` 复现：`tar -caf archive.zip --directory parent -source` 把合法目录名解释为选项，返回 `no files or directories specified`。归档参数数组在 leaf 前加入 `--`，并新增 `-source/payload.txt` 归档回归；仍使用 `QProcess` 参数数组，不引入 shell 字符串或旁路。

### 3.7 PBDisplayDiagnostics 独立目标依赖应用模型的传递 include

全目标 Release 编译首次暴露 `PBDisplayDiagnostics` 无法找到 `pbcore/stage_diagnostics.h`。根因是 `monitor_catalog.h` 不必要地包含 `application_model.h`，独立显示诊断工具因此隐式依赖完整应用模型；移除该传递 include，并在 `monitor_catalog.cpp` 保留其固定 1920×1080 画布常量。独立工具随后成功编译，应用/测试目标也重新编译通过。

### 3.8 ProtocolDump 测试残留退役 Profile 身份

`PBProtocolDumpTests` 仍期望退役的 `PB-Unified-LC1`（`5042554e494c4331`），而当前正式身份是 `PB-Unified-SC6-V3`（`5042554e49534333`）。仅更新测试期望值，未改变协议或运行时身份。

### 3.9 Step21 kit 工具引用已删除的历史文档

Computer-B kit 生成器硬编码了文档清理前已删除的三条 `REMOTE_VISUAL_*` 路径，导致独立 CTest 在复制 operator docs 时失败。改为当前维护的运行时选项、项目现状、证据索引和 Encoder 指南；历史路线通过 `DOC_HISTORY.md` 恢复，当前工具 README 的同类路径也改为当前索引/历史入口。

### 4.2 仍然失败/跳过的权威证据

当前 `PBApplicationTests` 的权威结果为 **194 tests：192 passed、1 failed、1 skipped**。唯一失败是：

```text
test_unified_encoder_workflow.cpp:1869
probe.senderLogicalFrames - firstObservedFrame < 12000
actual: 12505 (loss model 3, firstObservedFrame 15000)
```

最终文件、WholeFileDigest、安全发布、最终重开和资源上限断言均通过；跳过项是未设置真实 Replay 数据集根目录。该 failure 是历史已知的 GrayFast spatial late-join 性能门，不通过降低阈值、删除测试、增加 ACK/旁路或无界资源来“修复”。多个更激进的窗口/预算候选会造成其它损失模型的资源拒绝、未完成文件或更长尾部，因此恢复并保留当前设计和失败证据，列为后续窄调度研究项。

修复后的当前二进制完整回归为 **234 项：233 通过、1 失败、0 额外失败**；失败仅为上述历史 late-join，Step21 kit 与 ProtocolDump 两项均已通过独立重跑和完整回归。该数字属于当前构建树，不应与旧 v1.0 closeout 的 172/173 混用。

这意味着本次审计没有声称“全量 CTest 全绿”、真实远控吞吐认证、一小时无停滞、单物理显示器硬件验收或 500 GiB 实测。

## 5. 保留限制与后续方向

1. Late-join 的 12,505 帧历史门仍需独立调度研究；任何候选必须同时通过所有 loss model、资源/冲突/摘要/发布/重开断言，并重新评估远控证据边界。
2. Shell 文件夹归档在 UI 线程中进行目录预检和等待 `tar.exe`；当前条目/字节资源有界，但超大或异常慢的本地目录没有可取消进度 UI。这是交互/可观测性改进项。
3. 真实非本机、实际显示器热插拔/HDR/适配器移除、单物理显示器和大文件现场测试仍按 `PROJECT_STATUS`/`EVIDENCE_INDEX` 的限制解释。

## 6. 纯视觉与安全复核结论

本次修复没有修改 Citrix/网络设置，没有新增反向通道或隐式 ACK，没有改变摘要、safe publish、final reopen、冲突拒绝或资源限制；字段重命名不涉及 wire layout。左屏、焦点、鼠标、键盘和真实远控画面均未操作。
