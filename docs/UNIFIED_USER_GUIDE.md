# PixelBridge 使用指南

**简体中文** | [English](USER_GUIDE.en.md)

## 1. 准备

文件在远程电脑上运行 Encoder，需要文件的电脑运行 Decoder。两端为 Windows x64。按正式交付包随附要求解压**整个目录**，不要仅复制 EXE、混用旧 Qt DLL 或跨版本覆盖文件。v1.0 的 Encoder 与 Decoder 分别打包，每包都附有独立中英文操作说明。

远控连接由您现有的软件提供。PixelBridge 不需要修改网络、远控画质或驱动设置，也不建立隐藏文件传输通道。

准备可写输出目录和足够磁盘空间。源文件传输期间不得修改；不要删除 Encoder 会话缓存或 Decoder 的 `.part` / `.resume` 文件。

## 2. 选择模式

双端必须一致：标准、灰阶高速、PAM4 或 PAM4 Wide。模式名称不带研发阶段标签；请选择适合实际源码面尺寸的模式。

Encoder 和 Decoder GUI 在新安装、缺失或非法 `g22/carrier` 偏好时默认选择 PAM4（索引 2）；已经保存的合法索引继续保持原来的模式（0=标准、1=灰阶高速、2=PAM4、3=PAM4 Wide）。这是 GUI 初始选择，不改变 CLI/core 的既有默认或 Profile/Wire 身份。

- 1080P 发送端：可用 PAM4，固定 1920×1080 源码面。
- 1440P / 1600P 发送端：可容纳 PAM4 Wide 的固定 2560×1440 源码面。
- Wide 不能直接缩进 1080P。数据窗口可全屏，但允许静态边缘；速度与正确性优先于铺满。
- 分辨率指物理像素，不是 DPI 缩放后的逻辑窗口尺寸。
- 当前 PAM4 家族 GUI 仅接受未旋转且不超过 3840×2160 的发送屏幕；不以自动缩小码面掩盖不支持的几何。
- 保留既有标准/灰阶选择以兼容相应会话；PAM4 家族不能与它们混收。

Sender 刷新率可设置 1–60 Hz，开始后锁定。当前 ToDesk 留存大文件结果使用 Wide 25 Hz，但不是所有远控环境的最优值；不要把 60 Hz 当作必然更快。参数变化停止后生效，不要在会话中变更身份。

## 3. 接收顺序：Decoder 优先

1. Decoder 选择保存目录。
2. 选择真正显示远控画面的那块屏幕，点击“整屏”或框选完整码面。不要把左上角定位/校准区裁掉。
3. 如需性能模式，先在高级选项设置内存预算。接收中不能修改。
4. **先点击 Decoder 的“开始接收”。** 没有 Encoder 画面时等待是正常的。
5. 远程 Encoder 选文件，确认窗口所在的目标显示器，点击开始发送。
6. 保持完整码面可见，收起远控诊断面板、聊天/悬浮工具及其它遮挡。
7. Decoder 明确显示“已完成”后，再由您停止 Encoder。

Decoder 点击“开始接收”后的 GUI 活动“已花费时间”从首次接受并通过当前 Profile 身份校验的 `SessionDescriptor` 开始；Encoder 尚未显示有效码面前的等待不计入。活动窗口包含恢复、写盘、整文件摘要、安全发布和最终重开复验。完成时 GUI 平均速度使用文件总字节数除以冻结的活动耗时；正式 `runStarted/runEnded` 与 verified raw goodput 仍保持完整运行/性能证据口径。

Encoder 没有收到接收完成 ACK。持续轮播、经过多轮、CRC 通过或 `.resume` 变大，都不能代替 Decoder 的完成状态。

## 4. 只有一块显示器

PAM4 家族 GUI 已支持所选单屏的整屏或区域捕获，不要求另一块保护屏，也不需要给 Decoder 界面留一块空地。开始接收后，可以让远控画面覆盖 Decoder 主窗口，接收仍在后台运行。

PixelBridge 不会替您移动、最小化窗口、抢焦点或模拟输入。若要查看进度，请自行选择不会长期遮住码面的方式；检查后恢复完整画面。实际单物理屏幕电脑目前未单独验收，已验证的是双屏电脑中的指定屏幕入口。

显示模式/设备/DPI 等改变会使当前捕获权限失效，需要检查提示、停止并重新选择，不会静默抓取另一块屏。

## 5. 已接收大小暂时不涨，怎么办？

“已接收大小”含已验证字节与接收中估算，**不是每收一帧就必须增加**。重复块不增加独立信息；分段可能还差几个修复块；估算接近段容量后仍可能需要额外方程。最终 100% 还要等整文件验证及复验。

| 当前提示 | 含义 | 建议 |
| --- | --- | --- |
| 补齐修复块 | 新的有效纠删块仍在进入，段尚未完成 | 正常等待，不要暂停 |
| 等待轮播 | 观察到重复/已完成段，等待缺失修复 | 短时正常；继续接收，不要暂停 |
| 校验分段、写盘、保存断点 | 正在执行真实恢复/持久化操作 | 正常，不要暂停或强制结束 |
| 整文件校验、安全保存、重开 | 数据恢复尾部检查 | 正常，完成前不要使用最终结果 |
| 解码资源暂缓 | 活动状态占用预算，新段暂时进不来 | 先等待；频繁发生时下次检查预算 |
| 捕获中断/无新码面 | 没有新的可用捕获或视觉数据 | 检查远控连接、遮挡、模式与 Encoder |
| 至少 30 秒无新有效块/验证段 | 仅凭现有观测无法判定正常 | 保持接收并检查，保存双端日志 |
| 明确错误 | 接收不能正常继续 | 按错误处理，不能当正常等待 |

**正常等待时请不要暂停。** 不要因短时大小不涨反复停止/重启；这可能增加恢复和错过后续码面的成本。异常时也不要盲目删断点，先保存日志。

## 6. 内存预算

灰阶高速 / PAM4 / Wide 在高级选项中可启用“按内存预算接收”。未启用仍保留 8 个活动解码器。默认总 1024 MiB、单实例 512 MiB。

可点击本机建议，按当前可用物理/commit 内存规划；预算不是整个进程的 RAM 硬上限。大内存有助于保留更多未完成分段，但过度占用导致换页可能更慢。[详细规则](DECODER_MEMORY_BUDGET.md)

## 7. 停止与恢复

- 正常停止会尽可能保存可验证断点；不要通过任务管理器强杀替代正常停止。
- Encoder 使用原源文件及原缓存恢复同一个 Session；Decoder 使用原输出目录及可验证断点。
- 不要修改源文件、手工编辑 `.resume`、随意搬走 `.part`，或将另一 Session 当作旧断点继续。
- 重新打开时会重新检查断点和已完成段，耗时不等于重新传输。
- 缩小内存/日志预算后，旧断点可能不满足新策略；程序拒绝而不是静默丢弃原状态。恢复合适预算后再试。
- 只有摘要、安全发布和最终重开全部通过的文件才可接受；已有同名最终文件不会被静默覆盖。

## 8. 日志与排查

高级选项中“打开日志目录”会打开本端文件夹。自动日志为 `run-<id>.events.jsonl`，正常停止/失败/完成后有同名 `.summary.json`。默认每 2 秒采样，记录当前操作、有效块/重复/资源/捕获等累计值。完整说明见 [诊断指南](DIAGNOSTICS.md)。

排查时一起提供双端日志、同一 Session 的标识、文件大小、模式、发送频率和远控环境说明。不要上传源文件、接收文件或截图作为日志的替代；分享前检查报告里的文件名和本地路径。

## 9. 注意事项

- **Decoder 先收，Encoder 后发。**
- **大文件大小短时不涨可能正常；正常等待不要暂停。**
- 不遮挡或裁掉码面，不在传输时改分辨率/显示模式。
- 不以屏幕 FPS 或网络面板流量直接换算文件速度。
- 100 MB 以下测试不一定覆盖大文件调度与长尾；真实速度承诺只能来自匹配环境的完整文件结果。
- 本次版本不承诺任意远控软件/分辨率/缩放/HDR，也不把离线 MP4 设计作为可用功能。
