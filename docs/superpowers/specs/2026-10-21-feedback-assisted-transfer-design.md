# 可选文件反馈辅助传输：实现设计

日期：2026-10-21。状态：**用户已批准本设计与详细实现计划并选择当前会话实施；运行时/GUI已接入，报告文档与最终复核/交付收尾中。**

研究依据：[可行性评估](../../FEEDBACK_ASSISTED_TRANSFER_RESEARCH.md)。本设计将研究中的候选选择收敛为可实施、可本地验证的单项功能；不以现场实验作为开始实现的前置条件，也不宣称本地验证证明真实链路提速。

## 1. 目标与已确认范围

PixelBridge 的目标仍是 Windows x64 非本机远控中的正确整文件视觉传输，优化指标为 WholeFileDigest、安全发布和最终重开后的总完成时间。项目主阶段仍是 v1.0 稳定性/显示兼容性/交付维护；本轮增加一个显式可选辅助控制面，不重启旧全量静态审计。

用户已确认：

1. 一个 Encoder 服务一个指定 Decoder。
2. Decoder 可写本地专用目录/文件；Encoder 经对应映射只读，更新可能延迟数秒。
3. 两端分别选择对应位置，仍先接收后发送；不开启保持原行为。
4. 文件完整验证后，Encoder 自动安全停止。
5. 标准、灰阶高速、PAM4、PAM4 Wide 全部支持，不沿用旧速度先验的 PAM4-only/>12 段限制。
6. Decoder 完成后显示“已完成，反馈监听中”，继续观察画面和发布状态，直到用户主动停止或关闭；不再恢复/重写文件，完成耗时冻结。
7. 先实现并进行本地工程验证，真实映射/远控效果由用户以后实机验证。
8. 最终交付最新 Encoder、Decoder 两个独立、带依赖的候选 ZIP，不覆盖旧正式包，不自行提交或推送 Git。

用户确认的是产品范围。本文及后续详细计划仍需各自审阅；低层 API、序列化、资源与测试选择由实现者论证，不要求用户选择技术细节。

## 2. 非目标与不可破坏的合同

- 正向文件内容仍完全来自 Decoder 实际捕获像素；反馈不携带源字节、恢复块、图像、脚本或任意命令。
- 不接入 PBBridge、网络服务端、剪贴板或远端按键注入。
- 不更改视觉 wire/Profile 身份、固定 Control 布局、FEC 方程、Golden 原有字节、DirectRepeat 或原恢复格式。
- 不更换 Wirehair，不增加全文件驻留或无界活动解码器，不放宽冲突/摘要/资源规则。
- 不实现逐方程 ACK、动态 FPS/Profile、自适应调制、多接收端汇总或自动文件解压。
- 不把反馈当发送者认证，不承诺未知写者、Session cache 克隆/回滚及永久失联环境的可用性。
- 不执行真实映射/远控实验，不自动修改客户端映射、驱动、网络或缓存配置。

现行总体设计中“没有 ACK”的声明仅对原路径继续成立；实现时显式加入本可选控制面例外，不把开启后的运行标成完全无反馈。

## 3. 架构和依赖边界

分为以下窄模块，核心均不依赖 Qt：

| 模块 | 职责 |
| --- | --- |
| Feedback protocol | 完整快照的显式序列化/严格解析/完整性/身份与位图验证；无文件 I/O |
| Feedback policy/state | 接收世代、重复/回退、时效、实际提交帧范围、确认集合、统计与调度选择 |
| Feedback file I/O | 只读打开或本地安全发布、文件所有权检查、单写者锁；不执行命令 |
| Feedback I/O isolation | 有界隔离进程与元数据管道，主程序轮询已就绪结果、取消/终止和世代隔离 |
| Runtime integration | 权威段提交/完成/视觉观察导出；发送调度与本 run 内安全停止；完成监听 |
| Qt options/status | 双端路径设置与状态，Encoder 主/Shell 共用；不进入协议/存储核心 |

隔离进程只处理反馈元数据文件读/写，不接触源文件、.part/.resume、编码载荷或捕获像素。它位于相同电脑，是为了隔离可能阻塞的 redirector I/O，不是额外的正向传输路径。

优先使用随包附带的 Qt-free PBFeedbackIo helper，两个端点各自可独立找到其同目录副本。启动使用绝对程序路径和正确 Windows 参数转义，不经过 shell；隐藏窗口、受 Job Object 管理。工具协议有版本、随机父子关联 token、精确长度和固定操作种类。

每个运行环境最多一个未结束 I/O helper；一次只允许一个操作，待写快照只有最新一份。超时后停止接受旧结果，结束 helper，确认退出前不再创建另一个；主 UI/呈现 owner 不阻塞等待网络调用。关闭使用有界等待与 job 终止，不派生无界线程或重试。驱动可能延迟子进程终止，主程序不把它加入无限 join。

## 4. 用户界面与配置

双端新增默认关闭的“文件反馈辅助”区域：

- 路径类型：目录或专用文件，默认目录；支持浏览与直接粘贴 UNC。
- Decoder 文案说明“本端写入反馈”；Encoder 说明“对应路径只读”。
- 目录模式由程序管理固定名称状态文件，不扫描其它内容；单文件模式只接受专用反馈文件，不覆盖无关已有文件。
- Encoder 主窗口、Shell 发送入口复用同一控件/偏好；Decoder 复用本端设置。启用和路径均在运行/停止收尾时锁定。
- 四个模式都可启用。非法/空路径在 Start 前明确拒绝；关闭不验证旧路径，也不访问它。
- 设置缺失默认关闭；损坏设置明确提示并关闭，不隐式创建映射或切换路径。

状态区分：关闭、等待匹配反馈、已生效、过期/不可达、反馈被拒绝、接收方已验证完成。显示配置启用和实际生效，不能把“配置了路径”写成“反馈已连接”。

Decoder 完成时保留已完成文件和冻结计时，显示“已完成，反馈监听中”；按钮允许明确停止监听，停止后仍保留已验证完成状态及“打开文件”能力。重新开始任务必须先安全结束旧监听，不能与新 run 并存。

2026-10-21 追加用户确认：完成监听期间允许对最终文件保持只读保护，仍可读取/打开查看；编辑、移动或删除前先停止反馈监听。不能用保护失败撤销已验证的历史完成，只能停止授权新的辅助完成凭据。

## 5. 快照语义与资源上界

采用独立的版本 1 二进制快照，不复用 RunReport、JSONL 或 PBJR 作为跨端格式。所有整数显式 little-endian，不持久化 struct 内存；解析采用 checked arithmetic、精确长度和 CRC32C，末尾额外数据/未知 mandatory 标志拒绝。

内容：

- 完整 SessionId、视觉 Profile/layout、原始文件长度、段数；
- canonical SessionDescriptor 与 FinalManifest 的 BLAKE3，缺 Manifest 时只报告等待，不能应用确认/终态；
- 随机 receiverEpoch、单调 snapshotSequence；随机写者实例标识不使用用户名或机器名；
- 精确的耐久完成位图，长度等于 ceil(segmentCount/8)，尾部未用位为零；
- 当前已准入视觉帧的 FrameSequence 和“观察可用”标志；
- 阶段、整文件摘要及三层最终验收结果；接收端冻结耗时可作为明确标记的 reported 字段；
- 不包含任何目录路径、文件内容或任意请求命令。

单快照最大 64 KiB；段数最多 65,536，位图最多 8 KiB。首版不发布逐方程 ID 或全部活动 decoder 清单。已完成集合的补集已足以指导有界窗口避开已完成段；更细需求提示不是本轮验收前提。

普通更新合并为约每秒一次，段完成和终态触发及时合并；读取约每秒一次。周期是保守工程起点，不称实测最优。相同状态可有心跳，但重复读取同一序号不续期；同序不同内容拒绝。调度提示默认 15 秒无新合格观察后失效；终态验证不套用这个短 TTL。

## 6. Decoder 的权威导出与完成恢复

分段完成位只能在现有 RecordCompletedSegment、CommitStoredSegment 和 storedSegments 更新全部成功后设置。FEC ready、CRC、估算进度和 unique symbol 数不得生成确认。

导出仅复制有界元数据到最新状态槽；文件发布不发生在 capture callback、GPU owner、FEC/存储提交临界区。辅助发布失败只影响反馈状态，不能让正确接收失败或未校验数据变可信。

文件终态依旧严格来自 PBStorage Publish 成功及实际 WholeFileDigest、安全发布、final reopen 结果。所有身份/位图/摘要/观察序号必须来自同一 Receiver 世代生成的同一不可变快照。

### 6.1 保留现有恢复凭据，不新建恢复格式

仅在反馈启用时，成功发布后保留当前已含 PublishIntent、绑定 reservation、Manifest 和 completed records 的 .resume。关闭时仍按原行为删除。

当前 CreateOrResume/CompleteRecoveredPublish 路径已经支持仅 final 存在时重新验证长度与摘要。反馈启用后的重启继续复用这条权威流程，验证完成前不能发布完成确认，不从反馈文件反向导入恢复状态。

不改变 PBJH/PBJR 字节或把 retained journal 宣称为文件内容验证的替代。完成后保留的 .resume 是明确说明的反馈恢复凭据；用户删除它会失去自动重启确认，但不会破坏已完成文件。关闭后旧凭据仍须按现有完整恢复规则处理，不能跳过摘要。

### 6.2 完成后的监听

反馈开启且不是 Replay/诊断模式时，完成后不立即结束 capture，而进入只观察已验证视觉身份的终态监听：

- 不再把 Transport 送入 Outer FEC、不写 .part、不增加 verified bytes，不继续累计文件完成时间；
- 只接受同 SessionTag、所选 Profile/layout 且通过现有有效帧检查的观察；
- 不使用 cadence tracker 的最大帧号，不能把 erased/Bootstrap-only 统计当权威观察；
- 不要求新的 Transport unique admission，以兼容空文件和恢复后直接完成；
- 观察新的当前发送帧后更新完整终态快照，支持 A 重启后的本次发送绑定；
- 用户停止/关闭/新任务会取消监听并使旧事件失效，已完成状态不降为失败。

最终状态文件保留，不能发布一次就删除。A 无写回 ACK，因此 B 只报告“已发布完成反馈”，不声称 A 已停止。新任务显式替代旧反馈世代；旧延迟读者只可安全回退，不能拼接两代状态。

### 6.3 最终文件事实的存续保护

仅启用反馈时，存储 owner 在最终重开摘要验证之前取得普通、单链接 final 的只读句柄，分享模式仅为 FILE_SHARE_READ；在同一对象句柄上完成长度和摘要验证，并持续持有到监听结束。这样新 Start 的视觉 witness 关联的是仍受保护、内容不可变的已验收文件，不是失去存续保证的缓存布尔值。恢复 final 也遵守同一链。已有写句柄/可写映射或不支持的提供者不能触发放宽共享语义；拿不到保护就不导出新终态，原文件完成和冻结耗时不被降为失败。关闭功能时维持原有文件句柄寿命。

## 7. Encoder 身份、新鲜度与自动停止

运行 owner 保存本次 Start 唯一 token，以及实际成功 Submit 的序号集合边界：空提交为空集；live 路径的区间为 firstActualSubmitted 到 nextActualSequence，不含上界。

以下都不是已发送证明：持久 lease end、仅已构帧、失败 Submit、snapshot 中自增后的 next 值、重复 Present。

快照只有同时满足下列条件才可影响调度：

1. 精确 Session/Profile/大小/段数及 canonical 身份匹配；
2. 视觉观察帧属于当前 Start 实际成功提交范围；
3. 通过完整解析、位图和阶段一致性检查，且写者/epoch 无冲突；
4. 当前本端 run token 未变化，序列/内容合法，新鲜度有效。

读取线程不能直接调用无世代条件的通用 RequestStop。最终完成事件必须带 Start token，通过当前运行 owner 的同步边界再次核验；只有本次 Session/Manifest 摘要和三层验收结果全部匹配才能沿原安全停止路径结束。日志停止原因明确区分用户、超时和接收方验证完成。

终态可以关联当前 Start 早先观察的合法帧，不因耗时较长的最终摘要而套短 TTL；但不能免除本次 Start、同一快照和完整身份绑定。

本方案依赖唯一 Sender、可信且未克隆/回滚的 Session cache。其目录锁/CRC 不是全局反回滚或认证。存在不可信写者、缓存复制或回滚时不承诺可信自动停止；本轮不默默修改视觉协议以增加挑战字段。

## 8. 四模式调度集成

反馈关闭时不创建 I/O/策略对象，现有分支与测试轨迹保持不变。

有效反馈开启时，在当前帧或 spatial bank 的完整提交边界更新下一次服务：

- 跳过/提前退休已耐久确认段的后续访问，不删除源、descriptor、encoded identity 或 repair high-water；
- 未完成段的候选集始终有限，最多现有六活动段，保持确定性扫描/回访游标；
- 不因为位图稀疏就把所有未完成段创建为 codec，不把未知当完成；
- 保留原首次 systematic 和合法后续 fresh repair 规则、DirectRepeat、Control 刷新；
- 早退 pass 时按已提交方程记账，并将已租未用 repair 范围安全退休，允许跳号、不重用；
- 所有段都确认但没有最终完成凭据时，继续显示合法控制/低浪费的既有服务画面，不停止，不捏造零段 Session；
- 反馈失效时停止使用确认掩码，保留当前不可变身份/ID 高水位并恢复原有全文件覆盖，不把已确认列表永久持久化为发送完成。

首版只用具体完成集合改变服务选择，不再加入另一套速率估算。PAM4 速度先验配置保留：反馈有效时真实确认优先，失效后恢复用户原来配置的无反馈策略；关闭反馈时先验行为完全不变。报告不能把该先验预测改称真实接收进度。

空间交织 bank、短文件 barrier、空文件和 DirectRepeat 必须各自经过真实生产 scheduler/Receiver/存储回归，不能只测 >12 段 PAM4。

## 9. 文件访问、安全与信任

Encoder helper 仅 GENERIC_READ、OPEN_EXISTING，使用允许发布者替换所需的共享模式；FILE_SHARE_DELETE 不赋予它删除权。不写测试文件、不建映射目录、不清理 B 文件。

Decoder helper 只写选定专用状态路径及自己的临时文件/锁。首次遇到已有非反馈文件、目录/reparse/非法对象或不一致锁时拒绝覆盖。同目录临时文件独占创建、写全和 flush；旧 primary 从同一已验证、拒绝写入的对象句柄退休到固定 .previous，再把新对象以 no-replace 改名到 primary。失败只对仍持有的旧对象尝试 no-replace 恢复；若目标已被别人创建，则保留新目标及一份完整 .previous，锁定辅助失败，等待显式处理，不删除/采用未知临时名。

2026-10-21 审阅后的安全收窄：Win32 按 pathname replace 没有 expected-file-ID CAS，因此不再承诺无间隙原子替换或失败后旧快照总在原名。切换中可能极短缺席，A 按不可读安全回退；每次可见对象仍是完整快照。占用的 .previous、.tmp、锁均不自动采用或覆盖。此实现不改变 PBFB 字节、视觉协议、A 只读或 helper 元数据边界。父目录 pin 也不是任意祖先目录竞争的完整证明。

Writer 必须等视觉 Session 初始化当前输出/恢复 reservation 后再启动。先将反馈 primary/临时/退休/锁的四个词法路径，与 final、part、journal、journal 临时路径按 Windows 大小写及词法规范化检查；冲突只禁用辅助，不能写入这些路径或让可选反馈抢占 payload reservation。该检查不在 owner 中访问远端文件，不改变恢复字节或已选 reservation，不宣称任意命名空间/祖先别名的全局证明。推荐物理独立的反馈子目录。

读取一次打开的有界完整对象，完整解析后整体应用；不以另一份 pathname stat 的长度信任内容。目录通知不是唯一正确性来源，不改全局 SMB/redirector 缓存，不从 mtime/轮询周期推导硬延迟上限。

基础信任模型是用户选择、由指定 Decoder 单写者管理的可信目录。校验和、公有摘要、SessionId 和帧号不认证写者。帮助文案明确不适合由不可信程序任意改写的共享位置；伪造反馈可能影响可用性，但不能使 Decoder 绕过文件校验。

## 10. 失败状态与可观测性

- 路径尚不存在/映射断开/超时/旧序号：显式等待或失效，继续原视觉发送，不无限停等。
- 错身份/畸形/同序不同内容/写者冲突：拒绝辅助输入，保留正确源/接收状态，不 latest-wins。
- 接收重启换 epoch：新权威恢复状态重新绑定，旧掩码/晚到 I/O 全部失效；不同快照不拼接。
- 最后快照发布失败：B 文件仍正确完成，提示辅助反馈失败；A 没有有效终态就继续发送，允许人工/原超时停止。
- 完成后退出监听：保持文件完成和冻结计时，不假装已通知 A。
- helper 丢失/版本不合：不暗中选择其它程序/通道，状态明确不可用，继续基线。

运行报告单独记录 requested/effective、状态/拒绝原因、accepted/stale/conflict/I/O timeout、观察帧、收到的确认段数、调度避开服务量、终态已发布/已接纳、安全停止原因和监听状态。只保留有界统计，不记录路径、payload 或持续事件队列。

接收方报告值使用 reported 前缀，不冒充 Encoder 独立验证或跨机可相减时间。Decoder 文件完成口径与监听时长分开。

## 11. 本地验收与候选包

本轮可执行本地构建、单元/集成/Golden/离屏 GUI、子进程故障和包检查，但不运行真实映射/远控实验。

必须覆盖：

1. codec 精确往返，截断/尾随/版本/标志/CRC/整数/位图/0和65,536段边界及冲突；
2. delayed/duplicate/reordered/stale 快照、跨 Session/Profile/Manifest/epoch、空实际提交集合、next/lease/future 帧号、Stop/Start 晚到完成；
3. 本地完整快照安全发布/只读读取、未拥有文件保护、单写者冲突、截断读取、helper故障/阻塞/终止/队列边界；
4. 四模式、0/1/6/12/13段、多窗口、RAW/压缩/DirectRepeat、早洞/尾洞、周期/突发丢失、资源压力和双方重启；
5. 分段确认前后耐久顺序，最终摘要/发布/reopen失败不得终态，反馈失败不得破坏正确完成；
6. 完成后监听不改文件/计时，保留 journal 的完整复验、B完成后A重启，以及用户停止/关闭/新任务；
7. disabled 零反馈I/O与旧调度/方程轨迹；已启用先验的回退；原标准/PAM4/Wide/Gray Fast回归与Golden；
8. 主/Shell/Decoder 设置、四模式可用、路径类型、损坏偏好、最小尺寸/滚动/DPI离屏布局及按钮生命周期；
9. 双端独立 Release 包的构建身份、helper/依赖闭包、清单/许可、全新解压、受限PATH离屏启动、包不变性及双端独立运行入口。

原失败测试不放宽：完整现有套件如仍出现历史 Gray Fast late-join 失败或缺 Replay 跳过，准确记录，不能报全仓全绿。与本功能相关的失败必须修复；未知 Critical/High 不交付为完成。

候选放在新的 artifacts 交付目录，两个 ZIP 各含所需 helper 和依赖，不覆盖 dist。沿用已封存依赖/对应源码与现有候选打包方式；不绕开正式 clean-commit 发布门禁，不将 dirty 候选称 ProductRelease。版本和源码内容身份必须可核对；不把本机路径/日志/设置写进待提交内容。

## 12. 实施顺序与完成标准

设计审阅后制定详细计划，顺序为：

1. snapshot/policy 的失败测试与纯实现；
2. helper/文件发布读取/取消隔离；
3. Decoder 权威导出、凭据保留和完成监听；
4. Encoder 四模式选择、时效回退及世代安全停止；
5. 双端主/Shell UI、状态/报告及文档；
6. 本地真实恢复链、离屏/故障、相关/完整回归，独立审阅和修复；
7. 双端候选 ZIP、独立解压验证和交付说明。

完成必须有对应源码、双端可运行候选包、当前源码的本地验证证据、已知失败/限制清单和最短使用步骤。未执行的真实映射/远控/实机提速留为用户后续验收，不冒充已经通过。本次目标在只写设计/计划、只编译或只跑狭窄测试时都不算完成。
