## 已有能力

- 双端 Windows x64 GUI；新安装、缺失或非法模式偏好默认 PAM4（索引 2），标准/灰阶高速兼容保留，Wide 仍可显式选择。
- PAM4 支持 1080P 源码面；Wide 固定 2560×1440，适合可容纳它的 1440P/1600P 源桌面。
- Decoder 选择单屏整屏/屏内 ROI，无保护第二屏或预留 UI 区要求；启动和运行期复核显示身份。
- 有限内存性能模式、总/单实例设置及主机建议；断点批量 checkpoint 与有界整理。
- 纯视觉单向 payload；分段/整文件摘要、安全发布与最终重开。
- 本次收尾增加双端自动日志、实际恢复活动解释及角色图标；定向验证结果在下方/交付审阅记录更新。
- Decoder GUI 活动接收计时从首个当前 Profile 的有效 `SessionDescriptor` 开始，排除此前等待；完成界面平均速度与冻结活动耗时使用同一窗口。正式完整运行时间和 verified goodput 口径保持不变。
- Encoder GUI/Runtime 支持本地“超时关闭（秒）”：`0` 表示人工停止，非零 `uint64_t` 秒数从本次 Start 被接受时计时并沿安全停止路径收尾；不进入协议或接收完成判断。
- Encoder 正常 GUI 启动会在当前用户 HKCU Shell 中幂等保留针对 `*` 和 `Directory` 的 `PixelBridgeEncoder` 静态右键 verb；右键入口打开小型刷新率/模式/超时对话框。文件夹输入先在本地有界压缩为标准 ZIP，再复用现有普通文件视觉传输、摘要、安全发布和最终重开链路；不改变 wire/Profile、Decoder 或 ACK 语义。
- 工作树保留 2026-10-09 的显式 Qt 软件呈现候选：主/Shell 窗口完全停止后可切换，每次新开窗口仍默认 D3D11，不持久化选择、不自动回退。其封存候选的本地验证与当前源码修改分开解释，真实 Citrix 冻结改善仍没有本轮现场验收。
- 共通文件字节上限为 500 GiB，分段数上限为 65,536；当前 PAM4/Wide GUI 的 7 MiB 默认分段对应 448 GiB 组合上限，详见 [预算与文件大小](DECODER_MEMORY_BUDGET.md)。

## 仍然重要的限制

远控视频内部码率/缩放/刷新决定可用信道；发送 Hz 不代表有效接收 Hz。PAM4 当前仍是 CPU reference readback 解调。没有 ACK，尾部可能等下一轮。更多 RAM 不是通用提速保证。日志可以分层定位，但无法仅凭两份日志唯一推断远控黑盒内部原因。
