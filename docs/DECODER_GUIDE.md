# PixelBridge v1.0 — Decoder 操作说明

**简体中文** | [English](DECODER_GUIDE.en.md)

## 两条重要提醒

1. **建议 Decoder 先开始接收，再开启 Encoder 发送。** 先等待发送画面属于正常状态，可减少错过开头控制信息的机会。
2. **接收大文件时，“已接收大小”可能暂时不涨，这是分段恢复中的正常现象之一，不要因此暂停。** 请看界面“当前正在做什么”：补齐修复块、等待轮播、校验分段、写盘或整文件校验期间应继续等待。明确错误、捕获中断和持续没有新有效块不应一概当作正常。

## 安装与环境

- 在需要接收文件的 Windows x64 电脑完整解压到新目录，运行 `PixelBridgeDecoder.exe`。不要只复制 EXE、混用其它版本 DLL 或覆盖旧目录。
- 要求 Windows 10 1903 或更新版本 / Windows 11、可用的 D3D11 图形/桌面捕获能力和现有远控画面。不是所有 OS、驱动、缩放方式或远控软件都经过单独验收。
- Qt 与 MSVC 运行库随包附带；不需要 Python、开发工具或 PBBridge。ICU、D3DCompiler_47、Windows API 由系统提供，缺失组件的精简系统不在支持范围。
- 准备可写、可用空间充足的输出目录；大文件建议使用支持大文件的 NTFS 卷。单文件当前准入上限 **500 GiB**，不是已实测上限；磁盘还需容纳断点/临时状态。
- 所有 payload 只从选定区域的真实像素恢复，无隐藏网络、剪贴板或共享文件通道。无需改网络/远控设置。

## 接收步骤

1. 选输出目录，选择与 Encoder 相同的模式。
2. 选真正呈现远控界面的屏幕，使用“整屏”或包含完整码面的屏内区域；不可裁掉定位/校准区。
3. 如需充分利用 RAM，在高级选项中启用“按内存预算接收”，使用本机建议，或调整总预算/单实例预算。接收开始后这些设置锁定。
4. **先点击“开始接收”，再开启远端 Encoder。**
5. 保持完整码面可见，收起悬浮诊断面板，不休眠、不改变分辨率/DPI/显示模式。窗口遮挡、压缩和缩放都会影响有效数据。
6. 等待 Decoder 明确显示成功完成，再停止 Encoder、使用最终文件。不能用 `.part`/`.resume` 变大、某个段完成或进度估算代替最终成功。

点击“开始接收”后，直到首次接受并校验当前 Profile 的 `SessionDescriptor` 之前，GUI 的活动“已花费时间”、平均速度和 ETA 不累计等待。活动窗口会继续包含恢复、写盘、整文件摘要、安全发布与最终重开复验；完成时平均速度按原始文件总字节数除以冻结活动耗时计算。正式 `runStarted/runEnded` 和 verified raw goodput 仍是完整运行/性能证据口径。

## 模式、分辨率与单屏

- **1080P 非本机场景优先尝试 PAM4，发送端从 25 Hz 起验证**；这是建议，不是每种远控环境的速度保证。
- PAM4 固定 1920×1080 源码面。PAM4 Wide 固定 2560×1440，适用于足够大的 1440P/1600P 源桌面；不能直接用于 1080P 源桌面。
- 标准是兼容保留的彩色形状/色度路线；灰阶高速使用多级灰阶减轻色度失真，但不保证比 PAM4 更快。两端模式必须一致。
- PAM4 家族支持所选单屏整屏/屏内区域接收，不要求额外保护屏。只有一块显示器时，可让远控窗口盖住 Decoder，后台继续接收；查看进度后恢复完整码面。
- 程序不替您移动/最小化窗口或模拟输入。单物理显示器电脑尚未独立实机验收；已测双屏电脑上只选择一块屏幕的入口。
- 显示身份改变会要求重新选择，而不是静默抓取其它屏。分辨率均指物理像素。

## 内存与等待

未启用预算模式时仍保留 8 个活动解码器。灰阶高速/PAM4/Wide 可启用预算模式；默认总预算 1024 MiB、单实例 512 MiB。内存多有助于容纳更多未完成分段，但预算不是整个进程的 RAM 上限。盲目占满内存造成换页会更慢；优先用本机建议，为系统、远控和其它应用留余量。

| 提示/现象 | 如何处理 |
| --- | --- |
| 修复块、轮播、校验、写盘、保存断点 | 正常恢复工作，继续等待，不要暂停 |
| 解码资源暂缓 | 先等待；频繁出现时在下一次接收前检查预算 |
| 30 秒或更久没有新有效块/验证段 | 保持接收并检查 Encoder、遮挡和连接，保存日志，不保证正常 |
| 捕获中断或明确错误 | 按提示排查，不可只等待；保留断点和日志 |

“已接收大小”含已验证字节与接收中估算，不是每个新帧都会增长。重复帧不增加独立信息，段内估算可能先到平台；最终还需整文件摘要、安全保存与重开验证。更多 RAM 不能解决视频压缩、缺帧或遮挡。

## 停止、恢复与日志

- 优先正常停止，保留同一输出目录中的 `.part`/`.resume`。它们是恢复数据，不是可以随便删的诊断日志。
- 同一个 Session 恢复时，Encoder 使用原源文件/缓存；Decoder 重新验证断点。已有同名最终文件不会被静默覆盖。
- 不要手改断点或把另一 Session 混进来；缩小预算后旧状态可能被拒绝，应恢复合适预算再试。
- 高级选项可打开日志；默认 `%LOCALAPPDATA%\PixelBridge\Logs\Decoder`，文件为 `run-<id>.events.jsonl` 与终态 `.summary.json`。
- 自动日志通常每 2 秒采样，有大小/时长/保留数量限制；强杀可能缺 summary。异常时及时复制双端同一 Session 的日志，并记录模式、Hz、文件大小和显示环境。
- 日志不含 payload/截图，但可能含路径、文件名和机器信息，分享前检查隐私。
